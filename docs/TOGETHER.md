# 一起听：两种模式

## 结论先说

**不用自建服务器。** 默认就是「云房间」，点一下就出房间号。

| | 云房间（默认） | 自建服务器（可选） |
| --- | --- | --- |
| 要准备什么 | 什么都不用 | 一台能跑二进制的机器 |
| 谁维护状态 | **房主的 App** | 服务器进程 |
| 房间号怎么来 | 本地生成 6 位数字 | 服务器分配 |
| 隐私 | 公共通道，猜到房间号能监听 | 只有你和服务器 |
| 稳定性 | 取决于公共 broker | 取决于你自己的部署 |
| 房主退出 | 房间结束 | 房间继续，房主自动移交 |
| 适用 | 临时和朋友听歌 | 长期固定小圈子 |

代码里两条路共用同一份房间状态机（`sync-core/src/room.rs` 的 `apply_client_msg`），
所以**行为完全一致**：切歌、暂停、拖进度、加歌、聊天、房主移交、踢人，一样都不少。
前端的 `useTogether` 也不需要区分模式，只是后端换了个 Transport。

## 云房间是怎么做的

那些油猴插件能"直接建房间"，原理都是**蹭一个公共中继**：大家连同一个第三方通道，
按房间号划分话题，房主的浏览器代替服务器算状态。BiliMusic 用的是同样的思路，
只是通道换成了公共 MQTT broker，比 WebSocket 中继更稳（自带心跳、支持断线重连）。

```
         ┌──────────────── 公共 MQTT broker ────────────────┐
         │        topic: bilimusic/v2/room/<房间号>          │
         └───▲──────────────▲──────────────────▲────────────┘
             │              │                  │
     Hello / Client    Server 广播        Hello / Client
             │              │                  │
        ┌────┴────┐    ┌────┴────┐        ┌────┴────┐
        │  房主    │    │  成员 B  │        │  成员 C  │
        │(跑状态机)│    │(只听广播)│        │(只听广播)│
        └─────────┘    └─────────┘        └─────────┘
```

- 谁进房：发一条 `Hello`；房主登记成员并单发一份 `Welcome`（含完整快照）。
- 谁操作：发一条 `Client`；房主收到后跑一遍状态机，把产生的 `ServerMsg` 广播出去。
- 房主自己点按钮：直接进本地状态机，不绕公共网络，所以没有额外延迟。
- 时间对齐：`State` 消息带 `server_time`，客户端算偏移后续本地推算（和自建模式完全同一套）。

信封用单字母 tag 省流量（公共 broker 上数据是明文计费的），
具体格式见 `sync-core/src/cloud.rs` 的 `Envelope`。

### 为什么选 MQTT 而不是 WebSocket 中继

- 公共 MQTT broker（EMQX 的 `broker.emqx.io`）**免费、不用注册、支持 WSS**，
  桌面和手机都能直连，不用为移动端单独开端口；
- MQTT 自带 keep-alive 心跳和主题订阅语义，不用自己写重连和 fan-out；
- 我们只需要 4 种包（CONNECT/SUBSCRIBE/PUBLISH/PINGREQ），
  所以客户端是手写的 100 多行（`sync-core/src/mqtt.rs`），没往依赖树里加东西。

### 想换成自己的 broker

设置里填 broker 地址即可，例如自建 EMQX/Mosquitto：

```bash
# Mosquitto 开 WebSocket 监听
listener 9001
protocol websockets
```

然后 App 里填 `ws://你的IP:9001/mqtt`（对应的 WebSocket 端口）。

## 自建服务器模式

需要的话还是老样子：

```bash
npm run sync:server:release      # 默认 0.0.0.0:8787
# 或
BIND=0.0.0.0:9000 cargo run --release --manifest-path server/Cargo.toml
```

然后 App 的「一起听」页 → 高级 → 填服务器地址。这个模式的优势是房主退出后
房间仍然存在（服务器端做房主自动移交），适合固定的小圈子长期用。

## 已知取舍

- **公共通道是明文的**：topic 只按房间号区分，任何人猜到号都能订阅。
  别在里面聊隐私，也别用同一个房间号长期复用。
- **房主是单点**：房主关掉 App，房间就结束了（客户端会收到 `Host { host: "" }`
  并立刻提示）。这也是"不用服务器"的必然代价——总得有人算状态。
- **公共 broker 可能限流**：EMQX 的公共节点对个人使用够用，但不保证 SLA。
  要是哪天不稳，切自建模式即可，代码在同一处。
